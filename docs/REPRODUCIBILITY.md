# Reproducibility and release procedure

## Exact environment

`environment.yml` and `requirements.txt` record the verified Python 3.9 release
environment. `pyproject.toml` defines compatible package ranges for installation.
The analysis manifest records the versions actually imported at run time.

## Determinism

- Development split seed: `20260629` (the split itself is created upstream and
  supplied as an independent file).
- Cross-validation seed: `20260629`.
- CP seed: `21207110`.
- CPR seed: `21153296`.
- CPRD seed: `20285464`.
- RD seed: `20330496`.
- Evaluation bootstrap seed: `20260727`.

Parallel tree fitting is deterministic for the locked scikit-survival version
and fixed random seeds, subject to platform and numerical-library differences.

## Required archive for a manuscript result

Archive privately:

- immutable development and validation source hashes;
- the locked split manifest and cohort-flow log;
- `configs/paper.yaml`;
- build and evaluation manifests;
- the prediction-manifest SHA-256 recorded in an immutable log before outcomes
  are opened;
- model registry, feature rankings, selected variables, and tuning results;
- aggregate validation tables and final figures;
- private model bundles and predictions under the applicable governance policy;
- the exact Git commit and tagged release.

Do not archive patient-level material in a public GitHub repository.

## Release checklist

1. Run `python -m pytest` and `ruff check src tests scripts`.
2. Run the synthetic smoke test on a clean environment.
3. Confirm `git status` contains no data, artifacts, outputs, absolute local
   paths, credentials, or generated model bundles.
4. Run a secret scanner and inspect all files larger than 5 MB.
5. Confirm CP/CPR/CPRD/RD terminology matches the manuscript.
6. Confirm manuscript numbers were generated by the strict run represented by
   the release commit; never mix estimates from another model chain.
7. Update `CITATION.cff` with the final author list and repository URL.
8. Keep reference implementations on a `v0.x` release. Tag `v1.0.0` only after
   the complete strict manuscript analysis has been rerun and locked.
9. Archive that tag with Zenodo and add the resulting DOI to the manuscript and
   repository metadata.
